From a memory address to a shared reader

A memory sheet is a runnable add-on with documented fields. Publish one from Share, or export its JSON. Community → Public memory sheets lets players search labels, addresses, and game codes, inspect definitions, and use a release as a starting point.

1. Direct values

Unsigned numbers are little-endian. A field carries a label, a read definition, and optional discovery notes. For English FireRed revision 0, the compiled reader uses a party base of 0x02024284. Each party record is 100 bytes; current HP is at byte 86 and maximum HP at byte 88.

{
  "label": "First party member HP",
  "read": { "u16": "0x020242DA" },
  "max": { "u16": "0x020242DC" },
  "hint": "Party base +86 / +88. Read after loading a save with a party."
}

These offsets come from TinyBird's pokemon_frlg.rs party profiles and party-record decoder. The workshop example also supports English Emerald revision 0. ROM hacks may retain the original game code while changing the layout; test your own dump.

2. Pointer paths

A direct address may move after loading another save. When a stable location contains a pointer to the object, use a pointer path. This illustrative path reads a 32-bit pointer from 0x03000000, adds 4, and reads a 16-bit value there. It is a syntax example, not a verified game address.

{ "label": "Example stat", "read": { "u16": { "at": "0x03000000", "deref": [4] } } }

Each additional offset reads another pointer and then adds that offset. Test pointer paths across resets and save loads. Use the advanced JSON editor for paths and repeated cards.

3. Text and encoded data

{ "label": "ROM code", "read": { "text": { "at": "0x080000AC", "len": 4 } } }

Text reads and text searches use ASCII. Pokémon names use a custom alphabet; parts of Pokémon records are also encrypted and reordered. TinyBird's compiled reader handles those transformations. A plain address sheet cannot reproduce a custom decoder. Search raw bytes with patterns such as 0F ?? 2A 00 when you know part of the stored representation.

4. Document what you found

Record the meaning, type, game version, when the value is valid, and how you tested it. Include whether a reset or save load changes the address. Unknown starting values, changed/unchanged scans, numeric ranges, and scanning every byte can help narrow candidates. A matching address is a candidate until you test it in different game situations.

5. Share the definitions

Sheets use the existing manifest format and add "$comment": {"kind":"memory_sheet","memory_sheet_version":1}. Publishing creates an immutable community release with your description and license. It shares definitions and notes, not ROMs, saves, or memory snapshots. Copies retain their source release, author, and license metadata.

Compatibility is currently game code plus revision. Shared sheets are author-contributed findings; they are not automatically verified for every ROM.

6. Use discovered values from Python

For a plain numeric field, click Use this address for automation in the Workshop. Give it a name such as player.hp, click Add observation, and verify its live value. Automation observations lets you edit, remove, import, and export these definitions independently of your reader.

The exported configuration includes the loaded game's code and revision. The headless runtime checks both before applying it. Start from the same save state if the address only becomes meaningful after reaching a particular point in the game.

From a TinyBird source checkout:

cargo build -p tinybird-runtime
python examples/python/run_observations.py game.gba CODE-rN.observations.json --executable target/debug/tinybird-headless --steps 60 --frames 4 --buttons RIGHT

On Windows, append .exe to the executable path. Add --state game.state or --bios gba_bios.bin as needed. The Python client in examples/python/tinybird.py accepts observations="CODE-rN.observations.json"; each reset or step returns named values in observation["memory"].

This first version supports direct unsigned 8-, 16-, and 32-bit values. Encoded fields and pointer chains need a later observation format. ROM hacks that reuse a game's header still require address verification.
