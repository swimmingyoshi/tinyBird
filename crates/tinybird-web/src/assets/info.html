Where things stand

An honest read-out rather than a feature list: what the emulator does well, what is half-built, and what is knowingly missing. The long versions live in the repository's docs/; this is the short one.

Asset bytes come straight from the CDN; the API key stays on the server and is only used to list the vault and store save states. A missing BIOS is the difference between a correct picture and a corrupt one, which is why it is on this list.

The pieces

tinybird-core
CPU, bus, BIOS high-level emulation, DMA, timers, PPU, APU, save types, savestates, link cable.
tinybird-desktop
Windowed runner: audio, keyboard and gamepad, battery saves, quicksave, addon dashboard.
tinybird-web
This server: the browser build, save vault, accounts, rooms.
tinybird-wasm
The core as a WebAssembly module with a plain C ABI. No wasm-bindgen.
tinybird-addons
The addon contract: schema, memory view, registry, manifests. Addons are JSON, not code.
tinybird-games
Shipped addons: FireRed/LeafGreen, Final Fantasy Tactics Advance, and a fallback that claims any cartridge.
tinybird-probe
The address-finding tool: diffing, scanning, text search.

Roughly 650 Rust tests and 74 browser-module tests. CI builds and tests the non-windowing crates, runs the GBA accuracy suite as a gate, and builds the WebAssembly module.

What it does well

  • Solid Running commercial cartridges

    Fire Red, Pokémon Pinball, Final Fantasy Tactics Advance, The Minish Cap and Super Mario Advance 4 all boot, render and save. Nothing outstanding on any of the five.

  • Solid One core, three surfaces

    The desktop app, this browser build and the stream overlay run the same emulator. Not three implementations kept in step — one, compiled three ways.

  • Solid Reading a running game

    Addons are JSON, not code. Move, species and item names are read out of the cartridge by searching it for a known name, so they are right for any build — ROM hacks included — rather than depending on a table that matches one release.

  • Solid Saves that survive the browser

    Battery saves and savestates, stored per account in a vault, and claimable if they were made before you had an account.

  • Solid The link cable

    The handshake completes, both players reach the same Trade Center, and position data crosses in both directions — thousands of transfers against zero for the control run.

Being worked on

  • In progress Trading a Pokémon

    The cable is done; the exchange is not. What is missing is the button sequence that opens the trade menu — pressing a button on an exact tile, which is a puppeteering problem rather than an emulation one. The harness now proves no exchange happens rather than leaving it to a filmstrip: it reads both parties by their unencrypted personality values and reports either way.

  • In progress Fast forward past 1.4×

    A frame costs about 11.8 ms in the browser against a 16.74 ms budget, so fast forward tops out near 1.4×. Batching the APU tick bought 19% of that; the rest is CPU and PPU work that has not been won yet.

  • In progress The stream overlay

    Switched off on purpose. It still reads the desktop app's JSON export rather than the emulator in the page beside it, so on a server run by itself it shows a snapshot that never changes. Nothing was deleted — TINYBIRD_WEB_OVERLAY=1 brings it back. Pointing it at the WebAssembly snapshot is what would make it worth switching on again.

Known gaps

Listed because they are real, not because they are next. Each is written up properly where it belongs in the repository.

  • Gap A vault URL is unlisted, not protected

    Listings are scoped to the signed-in account, but anyone given a screenshot's CDN URL can open it. The private path that /api/saves uses has no equivalent for pictures yet.

  • Gap Screenshots cannot be deleted from the page

    The gallery lists your own and opens one full size. Removing one means removing it from the vault by hand.

  • Gap Some numbers are still compiled tables

    PP and catch rates live in differently-shaped structures than names do, and have not had the read-it-from-the-cartridge treatment that made the names hack-proof.

  • Gap Gamepad axes beyond the left stick

    A pad with only a right stick or a hat switch reports no direction.

  • Gap Addons need a reload

    Manifests are fetched once at boot and the registry is built on first use, so changing one means reloading the page.

  • Gap Lint and format backlogs

    cargo clippy runs in CI as reporting only, and there is no cargo fmt --check, because the tree predates both. The path to turning them on is in the CI workflow.

Run it yourself

Neither ROMs nor a BIOS dump are in the repository, and .gitignore is set up to keep it that way. 

# Desktop
cargo run --release -- roms/game.gba

# This page, plus the overlay server
rustup target add wasm32-unknown-unknown
cargo build -p tinybird-wasm --target wasm32-unknown-unknown --release
cargo run -p tinybird-web

# Optional: point it at your asset vault
cp .env.example .env   # then set TINYBIRD_MEDIA_KEY

A BIOS dump at gba_bios.bin is optional for most games and required for FireRed, which decompresses its graphics through BIOS calls the high-level stand-ins do not cover well enough.

Found something else?

A cartridge that renders wrong is worth reporting even if it is not on this page — say which one, and whether a BIOS dump is in place. The contact form reaches a person.
